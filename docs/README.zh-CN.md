# 照护手记 Care Notes

**你不用把那几天记清楚，Care Notes 帮你把“到底发生了什么”重新拼出来。**

[使用指南](USER_GUIDE.md) · [项目状态](PROJECT_STATE.md) · [开发路线](ROADMAP.md)

Care Notes 是一个早期开源、手机优先的家庭照护项目。它要解决的不是“再做一个记笔记或看统计数据的 App”，而是一个更难的问题：

> 当被照护者无法、拒绝或不能可靠主动记录，家属手里只剩下一些零散、模糊、甚至互相不一致的描述时，怎样把这一段经过重新整理成**可核对、可追溯、知道哪里还不知道**的材料。

## 最低条件：一部手机就应该有用

Care Notes 的核心流程不能依赖智能手表、摄像头、Home Assistant、智能药盒或其他额外硬件。

**一部 Android 手机 + 一名照护者**，就应该能够完成核心工作：记录碎片、保留原话和来源、整理一段经过、核对缺失信息、确认或拒绝关联候选、导出交接材料。

以后有手表、Health Connect 或其他自愿接入的数据源，可以增加证据；没有它们，Care Notes 也不能失去核心价值。

## 招牌功能：事件重建

当前开发方向把“事件重建”放在最前面：

1. 把真正留下来的碎片记下来；
2. 原话、来源、不确定性和修改历史都保留；
3. 选择这一次需要整理的记录；
4. 找出还缺日期、来源不清、描述不确定、关联记录没有选全等问题；
5. 对“同一类别而且时间接近”的未关联记录，只提出一个**可能属于同一段变化**的候选；
6. 必须由家属查看两条原始记录后选择 **“关联这两条”** 或 **“不是同一段”**；
7. 系统绝不会因为时间接近就自己合并；
8. 最后导出仍然能够回到每一条原始记录的交接内容。

拒绝一个候选，只是保存在本机的审核选择，不会写进交接材料当成“事实”。接受关联以后，两条原始记录也仍然分别保留。

## 它故意不乱猜

Care Notes 的价值不是“AI 什么都知道”，而是在资料不足的时候仍然守住边界：

| 手里的碎片 | 不能偷偷升级成 |
| --- | --- |
| “我没看到她睡” | “她失眠了” |
| “我没看到她吃药” | “她漏服了” |
| 没有午饭记录 | “她没吃午饭” |
| 两名家属说法不同 | “其中一个人说错了” |
| 某一天完全没记录 | “那天什么都没发生” |

不知道就是不知道。冲突就是冲突。它们应该留在结果里，而不是被系统补成一个听起来完整的故事。

## 现在已经能做什么

当前开发线已经有：

- 一整段话录入后拆成草稿，并要求确认再保存；
- 原始摘录、来源、修改历史、备份与恢复；
- “整理经过”工作区；
- 人工关联的多条说法和遗漏关联记录提醒；
- 日期未知、来源未知、不确定描述等核实问题；
- 保守的“可能属于同一段变化”候选；
- 候选的明确接受 / 拒绝操作；
- 一套完全虚构、只依靠手机记录的多日测试案例；
- 交接文本与复诊摘要导出；
- **简体中文、英文、西班牙语、法语、日语、韩语**界面、帮助、事件重建文案和虚构示例；
- 浏览器本地保存和离线页面缓存。

这 6 种界面语言已经加入自动检查，包括字典键、占位符、示例、事件重建文案和关键流程。**目前没有宣称这些翻译经过独立母语人员或临床翻译验证。** 本地规则的文本归类模式仍主要面向中文和英文，所以“界面有某种语言”不等于“该语言的自动语义理解已经验证”。

当前静态试用流程使用本地确定性规则，**没有宣称已经会自动理解复杂事件**，也不提供诊断、治疗建议、换药决定、是否住院决定或临床验证结论。

## 怎么用

1. 先体验虚构示例，或进入“我的记录”写一段观察。
2. 打开“整理经过”。
3. 选择这一次需要整理的记录。
4. 核对缺失信息，以及“可能属于同一段变化”的候选。
5. 看过两条原始记录以后再决定是否关联。
6. 下载事件交接内容，或通过“导出”准备复诊摘要。

应用右上角还有“怎么用”。切换界面语言不会自动翻译或替换你自己输入的真实记录，原话始终保留。

## 最终产品形态

长期方向已经确定：

> **Android App 是主要成品，网页是公开 Demo / 电脑端查看与整理界面，事件重建 Core 是两边共用的底层技术。**

Android 以后可以增加本机权限、语音、Health Connect、通知和加密存储等原生能力；网页更适合公开演示和大屏核对。两边应该保持同一种 Care Notes 核心体验，而不是两个完全不同的产品。

当前记录仍保存在浏览器 localStorage，没有应用层加密和自动跨设备同步。换设备前请导出备份。当前版本仍是开发阶段，尚未发布安卓 APK。
